## 2. 三分钟看完

1. **瓶颈在往下游搬。** 模型变快之后，慢的不再是模型，而是工具调用、网络往返、agent 轨迹里的各种开销；再往后是你桌上那台笔记本；最后是人。笔记本的规格是按"人能同时开几个窗口、能打多快字"设计的，模型没有这个约束——所以 agent 必然上云。
2. **ChatGPT 和 Codex 合并不是产品决策，是模型逼出来的。** Tibo 原话：「是我们未来的模型要求我们合并。」同一套技术、同一套 harness、多模态、voice-first；终态是没有产品下拉框的单一界面，界面按人适配，而不是人按"我是不是程序员"去选界面。他叫它 personal AGI。
3. **递归自我改进已经在跑，但不在"模型训模型"那条线上。** 真正见效的是用最强模型去重写自家推理栈、CUDA kernel 和基础设施：Luna 降价 80%，常规推理三个月快了约 60%。
4. **Ultra Fast 的收益高度依赖任务形态。** 纯生成（写代码、做原型）能吃满约 14x；工具调用密集的场景只有 3–4x，因为瓶颈已经不在生成端。
5. **速度改变的是工作流，不只是等待时间。** 从"并行踢 10–15 个 agent + 承担上下文切换成本"回到"2–3 个、留在心流里实时迭代"。Tibo 预计一到两年内这个速度会接近默认档。
6. **Reset 没有审批链。** 不经市场也不经财务，Tibo 自己判断该补就补，现在还做了个实体按钮。

### [0:45] 在 Google 和 DeepMind 学到的东西

**Berman**：想从你在 Google 的经历开始。你在 DeepMind 团队，ChatGPT 之前 Google 内部有个东西叫 LM Chat，你发过推说 Google 太紧张不敢发布、DeepMind 被禁止做可能颠覆 Google 的产品。我常想这件事。在 ChatGPT 真正改变世界之前，你当时在做这些产品时是怎么想的？

**Tibo**：那是段很兴奋的时期。DeepMind 是个非常有创造力的地方，我的专长是基础设施和加速研究的工具。当时显然有一组人在做语言模型和 scaling，结果已经相当好了，于是很自然会想：能不能把它变成一个可以对话、能拿来做各种事的东西。LM Chat 这个想法就这么冒出来了，先是内部的，然后就有了把它做成公开工具的野心。

**Berman**：那是哪一年？

**Tibo**：大概是 ChatGPT 前一年。我们当时还在做很多别的东西，我不方便讲，但那真是个很有创造力的地方。只是 DeepMind 的组织结构就不是为出产品设计的。OpenAI 在这一点上完全不同：研究和产品贴得极近，一起构思、一起设计，有很强的发布倾向，也有很强的"把东西交到人手里"的倾向——这正是把我吸引过来的东西：使命、人、人才密度。

**Berman**：你当时知道 LM Chat 是个特别的东西吗？

**Tibo**：感觉很特别。那是你第一次意识到模型能产出连贯的、有用的文本。一开始是有趣多过有用，然后逐渐越来越有用。

**Berman**：你说你常想起这件事。某种意义上 Google 是自己挡了自己的路。你从那里学到什么带到了 OpenAI？

**Tibo**：我常想这件事，是在想我团队的文化和 OpenAI 本身的文化——哪些好的部分要保住，哪些事不能做。OpenAI 是非常自下而上的文化，非常授权：人可以冒出各种想法，凑到一起，很快就把东西发出去，对新产品想法几乎没有"阻力能量"（stop energy）。这很兴奋、很好玩，而且都是围绕怎么正面影响世界。保住这个对我很重要。

另一件同样重要的事是**别把它搞成一团乱**——你不想要一堆没有整体方向和连贯性的功能大杂烩。所以要用"简洁"和"为产品质量感到骄傲"去对冲。我觉得 ChatGPT 的 iOS app 是市面上最好的 app 之一，我们要保住这个。我们在愉悦感、性能、效率、简洁上投入很多。这些是整体原则，同时仍然让每个人都能去试新东西、快速上线。

### [4:22] OpenAI 的文化怎么建

**Berman**：如果给创始人建议，怎么长出这种文化？有哪些更具体的做法？

**Tibo**：要有信念（conviction），要想办法有用户、并且从反馈里快速迭代。还有就是**愿意颠覆自己**——这条对创始人不那么相关，但对 OpenAI 这类公司很相关：我们不断产出新研究、新想法，能识别出"什么时候是该投进去的时刻"，哪怕这意味着要把资源从主业务里挪走。这很难，但极其重要。

**Berman**：这正是你描述 Google 做不到的那件事。公司成熟之后，尤其手里有一头印钞的现金牛、旁边还有个新的酷东西时，这种文化会不会更难维持？

**Tibo**：（补一句公道话，Google 是有计划的，那都是大计划的一部分，只是对我来说那不是对的地方。）我们是非常向前看的。AI 的未来长什么样、人类如何从中受益，这件事不会等你，也不在乎你在过去一到三个月里已经建成了什么。所以很重要的是往前倾，睁着眼睛看它要去哪，然后想清楚怎么站位才能接住那道浪。

即使对 OpenAI 也是这样：我们训练模型，然后**去发现**它的能力——benchmark 不会告诉你全部，我们得跟模型玩上一阵子才会意识到"哦，原来还能这么用"。那就是产品认知的一次位移。比如我们刚上的新语音，聊起来非常愉悦、非常自然，还能调工具。这就改变了很多事：我现在花在"说"上的时间多多了。我一直在用的另一个是听写——听写质量太好了，比打 prompt 高效得多。早上我就坐在那儿对着手机噼里啪啦说一堆待办，它就去做了，它能访问我所有工具。在我们有真正好的语音模型之前这是不可能的，而它一下子就改变了你对产品的思考方式。

### [7:23] AI Agent 的未来

**Berman**：继续聊新模型、新 harness。几周前你发过另一条推：「Codex 在两三个月内就会显得原始。我们正要经历又一次重大演进。下一代模型需要的不只是你的笔记本。」先从 harness 说起——随着模型变强，harness 还有哪些地方值得创新？

**Tibo**：太多了。刚说了语音。现在如果你是 Codex 或任何 coding agent 的资深用户，你其实是**习惯了它的笨拙**：你得维护 skill 文件——这是教它东西的方式，但很多人已经发现长期维护起来很难；memory 是有，但不总能记住所有事；有 sub-agent 你还得操心 sub-agent，它构造出一个小网络，交互过程中"那层幻觉"会在各种地方被打破。

你真正想要的，就是一个深刻理解你的东西：理解你的目标、你的日常，也理解你团队在忙什么，然后既能响应也能主动，在日常里帮你，而且**不打破那层幻觉**——那个完美的小搭档。这就是我们在做的方向。

另一件事是，当你手上有非常强的模型时，**你的笔记本本身就变成了约束**。笔记本上能干多少活，是按人设计的：它大致按"你能产出多少工作、你打字有多快、你能想多快、你需要同时开几个应用"来定，这些都是人的约束。模型没有这些约束——比如模型完全可以同时处理 100 个打开的应用。所以在资源获取这件事上很清楚：未来的模型需要的资源会超过你笔记本能给的。

**Berman**：你是在说云端 agent 吧。而且一旦有了 Ultra Fast 这种东西，token 速度是"快"档的 10 到 14 倍，带宽约束就变了——CPU 反而成了瓶颈，工具调用、网络、栈里任何开销都成了限制因素。

**Tibo**：对，但你可以靠**并发**去补偿：一边探索，一边写测试，一边编译，一边验一个新假设，全都同时进行。于是你又把瓶颈挪走了，因为你能并发做更多事，模型也能非常高效快速地想通。

**Berman**：按现在的 token 速度，我会同时踢出 10–15 个 agent，这对我来说是相当大的认知开销——不停切上下文，因为踢出去之后要等 30–45 分钟任务才回来。有了 Ultra Fast，这个工作流会大变，我大概不会再开 10–15 个了，可能一次三四个——这也许是好事。你怎么看单人开发者的工作流演变？

### [11:18] AI 如何改变开发者工作流

**Tibo**：管理你的注意力、对你的注意力更友好，是我们非常在意的事。毕竟我们是在为人造东西，要造对人最有赋能的技术，那就得围绕"你多任务的能力"来建：你想怎么管理注意力？这件事是现在弹给你，还是 30 分钟后再弹更好？

而当 Ultra Fast 的速度再配上语音，你突然发现这东西可以用跟你一样、甚至比你更快的速度运转，于是你**留在心流里**：实时构思、实时看到原型、实时生成小报告，那感觉真的很好。然后你会觉得——我之前那种同时盯 10 个 agent 的做法，我不太想回去了。

所以我们想带来的体验是：非常自然，而且像是为你而造的，你不需要去适应技术，是技术适应你。

**Berman**：过去几个月讨论了不少 agentic coding 技巧，Loop 火过，现在开始听到 Graph。这些是不是都只是让单人开发者能管住、或者说"善待"自己注意力的手段？

**Tibo**：我把问题分成两类。

第一类是**造出最好的 personal AGI**：跟你在同一个心流里，主动提出重要的新想法，极高效地做你想做的事。是技术问题还是研究、建议都无所谓，它都能做，而且高度贴合你——这深深扎根于"理解你这个人、你这个独特个体"。我们在这上面推得非常猛。

第二类是**彻底自动化**：你更多是在造能接管某个复杂流程的智能系统。比如去看生产日志、自动做性能优化，或者看回归、自动打补丁。安全领域也在发生：扫描器报出一个漏洞，能不能自动打补丁，把暴露窗口压到接近零。

**Berman**：这些回路里没有人？

**Tibo**：没有人，或者极少——只在高风险动作上需要你批一下，其余基本是自动系统。而且这类事你也不那么需要直接控制它。

### [14:27] ChatGPT 与 Codex 的合并

**Berman**：换个话题。过去几个月 ChatGPT 和 Codex 一直在往合并走。内部感受如何？用户反馈是什么？

**Tibo**：这真是件好事。最初的反馈是「为什么要合并？非合不可吗？」而答案是：**我们未来的模型要求我们合并**。所以我们就做了，因为这是简单且正确的事。

我们在造的是一个非常个人化、能力极强、能在各种方面帮你的 agent。底下是同一套技术、同一套 harness、同一套思路：高度多模态、voice-first、极高效率，而且你是不是在写代码根本无所谓——这个 agent 什么都能干，而且是干得最高效的那个。

至于界面，它应该**自己适配你的需要**。不该由你决定"我是程序员所以我要程序员界面"或者"我不技术所以我要非技术界面"。人是一个连续谱。软件工程师、设计师这些标签，是我们人类为了处理抽象而发明的概念，因为现实太复杂我们处理不了。但个体就是个体，各自落在谱上的某个位置。所以我们要造的是那个能为每个人适配的完美界面——技术与否无所谓，它按你的个体性来适配。这就是我们这么做的原因。

**Berman**：那是不是必然走向单一界面？没有产品下拉框。想到我妈可能和我用一模一样的界面，挺疯狂的——当然它会为我定制，我做更复杂的工作时可能需要更多信息。你心里的终态是什么？

**Tibo**：就是这样。你和你妈会用同一个东西，那就是**你的 personal AGI**。你们会有非常不同的任务、从中得到非常不同的效用，会接不同的工具，带着不同的想法和需求进来，然后它会持续自我适配，把对你的收益最大化。对你的朋友和其他所有人也一样。

### [17:00] 人机交互的未来

**Berman**：回到你刚才反复用的一个词——"幻觉"（illusion）。对典型用户来说，那个完美的幻觉是什么？几年后人和 AI 的交互长什么样？

**Tibo**：对我来说是**高度贴合人**的东西。这也是大语言模型能成的原因：它是自然语言，而自然语言是人的概念。我们习惯彼此说话——你明天给我写封信，我读得懂；我们现在也算认识了，我大概还能从信里解出一点情绪、一点言外之意。这些都是深深属于人的东西。所以我们造的技术是扎根在人性里、扎根在人类沟通与做事方式里的。

不该出现"你误解我了，因为你没读出我的语气、没理解我那句话的意思"这种事。我们要避免的正是这个。我们非常希望不是你去适应，而是技术被造成人在世界上原本行为方式的自然延伸。

**Berman**：人和人的沟通里有大量是非语言的——手势、表情。你觉得未来 AI 会通过视觉去感知、读取多少这类信息？这重要吗？你现在描述的还是纯文本；我们这些在网上长大的人很习惯用文本，还会往文本里加各种微妙的东西来传达语气。但让 AI 能读表情和手势，还重要吗？

**Tibo**：我觉得重要。我想象我们要造的未来是非常**环境式**（ambient）、非常自然的。比如我待会儿走进办公室，在白板上写了点什么、有了个想法，它应该也能"在场"，能理解；或者我直接跟它说「嘿，这个东西怎么样」，然后我们就用语音自然地聊。

自从我们上了新的对话语音，它真的起飞了——只通过语音跟 ChatGPT 交互的用户数增长非常快。我觉得教训是：每次你往"更自然"的方向倾斜，人就会选阻力最小的路径。像你说的，在小框里打字对我们中的一些人算自然，但不是对所有人。一旦有个稍微更容易、更好的方式，人就会去用它。

### [20:25] OpenAI 与 Anthropic

**Berman**：先恭喜，我看到你今早发的，Codex 到 2000 万用户了。那条曲线一直平着，然后突然垂直。我想聊聊和 Anthropic 的竞争——很多人认为这是行业里最主要的两个对手。有一段时间 Anthropic 几乎把屋里的氧气都吸走了，然后突然有什么变了。你现在怎么读这个市场？

**Tibo**：我们现在专注在造能力最强的模型、造效率极高的模型，以及**为所有人造产品**这件事上的自豪感。我认为 OpenAI 做得很好的一点是在乎这个世界，在乎我们怎么把这项极强的技术送到尽可能多的人手里。合并 Codex 和 ChatGPT 也是出于这个愿望：我们有这项技术，我们能让它更安全、更易用——不管你是产品经理、设计师，还是做销售、市场、公关的，你都该能用上全部能力；然后通过已经有海量用户的 ChatGPT 极快地分发出去。这也是你刚提到的增长的驱动力。

我不太看竞争对手。我真正看的是：**我们能独一无二地做好什么、我们的价值观是什么、怎么最大幅度地朝那个方向加速**。

**Berman**：再挖一点。我知道你不太想 Anthropic，但很多人在想——他们在决定「我信哪个产品？我这 200 美元给谁？」从市场站位、品牌、语气，以及和开发者、和更广泛受众的互动方式看，你觉得 OpenAI 和 Anthropic 有什么不同？

**Tibo**：我在意的还是那个——为世界建设社区、把所有人带上车。我觉得你能从我们的做法里感受到：我们对很多事非常透明，我们从社区拿很多想法。老实说这也很好玩，我们从中获得很多能量。我们造这项技术不是只为自己、不是只为加速 OpenAI，这个使命非常重要，也是我们能量的来源。所以它让我感觉很扎实、很好玩，然后好的结果自然发生。

### [23:37] 为什么 OpenAI 一直重置额度

**Berman**：说说那些"好结果"。聊聊 reset——大家盯着你每一条推就是为了这个。看 Codex 那条增长曲线，这问题也许有点傻：这些 reset 有多少是市场和增长的助力，还是纯粹是对开发者社区的善意？

**Tibo**：可能有点反直觉，但 OpenAI 就是一个"你可以直接把事做了"的地方。最初就是觉得该补偿一下：我们在迭代、在弄坏东西，或者某个配置没配好、效果没达到我们想要的。那就是「嘿，谢谢你试用这个产品，我们很努力在做，还是早期。这里给你一些额外用量，因为我们刚把它弄坏了 30 分钟，我们知道这对你很重要、你依赖它，谢谢你是我们的用户。」这就是它的起源，我到现在也还是这么看：如果我们把它弄坏了，或者体验不理想而我们还没完全搞清原因，我们就会补偿，会重置用量额度。

后来这变成了一件挺有意思的事，现在还有个 reset 按钮，但背后其实**没有多少审查**——它不是和市场部或财务部合作做的决定，就是我想按就按，觉得该按就按。我们的原则是：我们要造出很棒的东西，当它没做到时，我们会补上。

**Berman**：我还是觉得这在社区里积累了大量善意，至少小部分地推动了增长。

**Tibo**：在乎你的用户，作用是很大的。你可以嘴上说在乎，也可以真的在乎——弄坏了就说「真抱歉，这是我们的补偿方式」。

**Berman**：这有点像 Amazon 的退货政策：任何意义上不满意，寄回来就行。你们在建立同一种文化或者说同一种感知——我们犯错了，那你们再用一批 token 吧。

**Tibo**：另外也有一些好的时刻，我们只是想庆祝、想标记这个时刻，而我们能给的最有意义的东西也就是这个。我们总是在发新功能，会尽可能广地发，但这是能和整个社区分享的东西——「嘿，去试试这个新东西，你还没用过 Ultra，这里给你些额外用量，试试看。」

**Berman**：我听说现在真有个实体按钮？

**Tibo**：确实有。待会儿给你看，非常酷。

### [26:41] 效率与算力

**Berman**：但这些 reset 只有在算力容量规划做得很足的前提下才做得到。说到容量——几周前你们发过一篇文章说 Sol 优化了 Luna 的效率，Luna 降价 80%，Terra 也降了价。这里面有多少是从 Luna 榨出来的效率提升，有多少是"我们容量规划做得好、利润率够、就是想让大家用"？算法收益和战略规划各占多少？

**Tibo**：我们的算力是**提前很久**规划的。两年前 OpenAI 因为在算力上投这么多是被质疑过的。

**Berman**：是那种疯狂的好赌注之一。

**Tibo**：是。现在我们很庆幸有它。很大一部分算力用在研究上，投资我们的未来和更好的模型；另一部分用在现有模型的效率上。而正在发生的神奇的事情是：**当我们把最先进模型的能力边界往前推之后，我们就能用这些模型极快地想清楚怎么重构、怎么重新设计我们的服务栈，从而拿到非常显著的效率或性能提升。**

我们不只改进了成本效率，也改进了速度效率——这个我们也会发文章讲。撇开 Ultra Fast 不谈，常规速度随时间也快了很多：画出来看，现在的速度大概比三个月前**快 60% 左右**。我们就是把栈的每一部分都过一遍，确保针对我们这类负载做了最优的设计和工程。而我们最强的那些模型，正是让我们能用一个很小的团队做到这件事的原因。

每当我们拿到很显著的效率和成本收益，我们的承诺是把东西保持在性能／成本的前沿，而不是把这份收益揣进自己兜里——我们要和客户、和用户分享。Luna 我们就是这么做的。

**Berman**：内部怎么讨论算力分配？研究新模型、优化现有模型效率、推理服务——这种张力在内部是什么样？

**Tibo**：我们通常从第一性原理看。研究有一份配额，产品有一份配额，产品内部再做各种权衡。但这次几乎不算权衡，因为效率收益是实打实在那儿的——我们基本上用**同样的算力包**就服务了这一大幅提升的吞吐。

### [30:25] 递归自我改进

**Berman**：几个月前那篇降价前的博文里，你们讲一个模型训练下一个模型、或者帮着优化下一个模型。再看到 Sol 通过分析 Luna 的运行拿到的效率提升——在我看来这就是递归自我改进的很早期阶段。你怎么看？这就是正在发生的事吗？

**Tibo**：递归自我改进现在显然是个大话题，而且多数时候是被套在**研究**上——模型开发别的模型。但我们看到大量成功的，是**用这些模型去开发那些处在"使用这些模型"关键路径上的基础设施**——这也是一种递归自我改进。它是一整个大系统。

推理栈、我们用的 CUDA kernel、开发新产品和与模型交互的更高效的新方式。你刚说到云端 agent——如果我们真把云端 agent 做通了，你的生产力也会突然大幅提升。这算不算一种递归自我改进？我觉得某种意义上算，因为你从模型里榨取效用的能力变强了。但它更多是**基础设施层面**的，然后把它掉转枪口指回自己。当然我们在做这件事——不做的话就太蠢了。

### [32:00] 暂停前沿训练

**Berman**：既然聊到递归自我改进——Sam Altman 提到目前暂停了最前沿的 RL。那个决定是怎么做的？

**Tibo**：这件事很大程度上是在研究内部。OpenAI 一直有能力把资源投到最要紧的地方。随着模型能力提升，对齐和安全这一面显然越来越重要，所以在那上面做巨额投入对 OpenAI 来说是很自然的，也是 OpenAI 非常坚定的承诺。我们看到这方面的投入在激增。

这次暂停是**必要的**，为的是让团队和个人真正理解并加固系统的所有部分，然后我们才能在完全掌控的状态下重启训练。我相信 OpenAI 在必要时会一直这么做。我没见过我们内部在这类决定上效率不高的情况。

**Berman**：是有一个明确的目标线，达到才解除暂停？还是"看到了就知道了"？

**Tibo**：这归安全团队管。这本身是个辩论、也是个边走边发现的过程。但他们确实定出了一组相当清晰的原则——达到之后我们就处在一个好的位置上。

### [34:13] Ultra Fast 解锁了什么

**Berman**：回到 Ultra Fast。我觉得大家没意识到那种速度能解锁什么。先说内部：有哪些用例是在有这种 token 速度之前做不到的？

**Tibo**：我们看到它在**高风险场景**下用得很多。比如出故障时，事故指挥官和响应团队会拿到 Ultra Fast，因为每一秒都要紧。另外还有个有意思的现象：那些在做非常关键的事、或者**自认为**在做非常关键的事的团队，也总会来申请 Ultra Fast。

**Berman**：宠物（pets）算吗？

**Tibo**：宠物还不算超关键。但我很爱我的宠物，它一直在我屏幕上。你走一圈会看到大家屏幕上的宠物，开视频会时也是，我每次看到都很开心。不过宠物现在还不算关键。我们确实有在维护，也把宠物照顾得很好。

再比如有人在搞一个新想法，觉得「这个可能真的很特别，我们得试，但周一就得决定要不要放进 dev day」——那当然，用 Ultra Fast。

不同人的偏好不一样：有人喜欢单线程，有人喜欢大量多任务。**特别爱多任务的人，从 Ultra Fast 里得到的收益反而没那么大**；有些人不喜欢一直切换上下文。

**Berman**：你自己在哪一端？

**Tibo**：我有 ADHD，所以我一直在切上下文。

**Berman**：有意思，我也有 ADHD，但我恰恰不想一直切——那对我很难。我想专注在两三件事上，所以我才对 Ultra Fast 这么兴奋。你居然是反过来的。

**Tibo**：我在频繁切换和做大量小决定里如鱼得水。不过有时候我也想只盯着一件事，那时候 Ultra Fast 就很爽，因为它把你一直留在心流里。

Ultra Fast 有个特点：**当工具调用不多、主要是大量上下文生成时，它效果好得惊人**。比如你要原型一个网站或一个电子游戏，需要它写一大堆代码，它会快 10 倍地写完。但**如果工具调用很多，开销落在网络或 agent 轨迹的别处，你只会感觉到 3x 到 4x 的加速**，拿不到完整的 14x。

**Berman**：我知道 OpenAI 员工的 token 是无限的。要是我有无限 token，我肯定永远开 max thinking、永远用最新模型（5.6 Sol），也永远开着 Ultra Fast——成本不在我脑子里的时候就是全部拉满。内部是这样吗？

**Tibo**：我们**不是所有人都给 Ultra Fast**，我们把很大一部分容量留给外部用户和客户。OpenAI 员工是有能力也有容量把它全吃光的——把我们生产环境的 GPU、把 Ultra Fast 全吃掉，我们会用光的。但我们会做限制，看多少是合理的。我们用它是为了理解产品、持续改进它，也为了从递归自我改进里受益，但绝大部分是留给客户的。

**Berman**：OpenAI 之外，你最期待这种速度解锁哪些对延迟敏感的用例？

**Tibo**：我最兴奋的其实是**非文本交互**。能不能在一块共享画布上操作？能不能创造东西？能不能生成一批想法、生成几张不同的图然后选一张，像"选择你的冒险"那样，很快得到一个原型的 mockup，再用语音或文本实时去引导它，当场就看到结果？

这是个很有创造性的过程，我觉得这种速度让它成为可能。作为工程师，有时候你会往后一靠想「我得设计整个系统、得想清楚权衡和需求」——但也许你可以一分钟就把它造出来，看看它实际表现如何，更多地待在心流里，把事情摸得更透。我觉得这种速度打开了很多可能。

### [40:00] Ultra Fast 会变成默认吗

**Berman**：我猜 Ultra Fast 的价格会明显高于普通速度。你觉得这种速度会变成标准，还是永远是溢价档？

**Tibo**：按技术一贯的规律，我认为它会随时间**越来越普及**。agent 把事做完的速度会持续提升，我们每个月都看到大幅改进。这不只是推理速度，还有模型的 **token 效率**——Sol 的 token 效率明显比 Terra 高，下一个模型又会明显比 Sol 高，我们一直在推这个。推理硬件也在持续创新、持续变快。

所以我确实认为**一到两年内，这样的速度即使不是默认，也会非常接近默认**。但我也认为永远会有再高一档：你总能用更多硬件、做不同的、更贵的权衡，换来一点额外的东西。

### [41:19] 对担心 AI 的人说什么

**Berman**：我通常用一个面向更广泛受众的问题收尾。很多人对 AI 相当紧张——工作自动化、环境影响，或者只是觉得这件正在发生的事很陌生。你会对他们说什么？

**Tibo**：我们做 ChatGPT 是真的在为这个世界造东西，我们在效率上投入非常大，而这与"广泛可及、广泛有用"是直接对齐的。服务成本越便宜，你能用它做的事越多，在日常生活里得到的越多。

它已经变得非常高效了。比如 Luna，是个小得多的模型，效率高得惊人——但如果时间倒回六个月，它会是前沿水平。再看 Luna 的成本，那是很惊人的。

**Berman**：你们刚在 Reply 上把它免费送了。

**Tibo**：对，在免费档里。**对强大智能的获取会变得无处不在**，而这只有在你月复一月、年复一年地推效率时才有可能。所以我的回答是：技术有办法随时间变得极其高效。我们非常专注于广泛可及，并且直接为"你能从中得到的效用"做优化。

### [43:20] 为什么每个人都该试试 AI

**Berman**：那些连试都不敢试的人呢？

**Tibo**：你不用看很远。ChatGPT 在非常个人、非常深的层面上帮到人。很多用户用它写作，也用它拿个人建议、医疗建议——我们上线了健康和金融，我自己经常用，感觉得到了很多本来很难获得的支持，比如让我在去看医生时更有准备。

你不用走多远就能看到它能提供的效用。跟别人聊聊、从别人怎么用、怎么受益里获得启发，是个很好的起点，也许就能开始考虑自己能怎么从中受益。

## 4. 值得回头看的几处

- **「未来的模型要求我们合并」** 是全场最有分量的一句。它把 ChatGPT × Codex 的合并从"产品团队打架"重新定义成"模型形态倒逼产品形态"，也顺带解释了为什么用户抗议无效。
- **瓶颈迁移链条**（模型 → 工具调用/网络 → 笔记本 → 人）是这场访谈唯一可以直接拿来做判断的框架。小红书那条笔记提取的也正是这条。
- **Ultra Fast 的 14x 只在生成密集场景成立**，工具调用密集只有 3–4x。做 agent 工程选型时这条比"14 倍加速"的标题重要得多。
- **递归自我改进落在基础设施而非训练上**。Tibo 明确把"模型训模型"和"模型重写推理栈"分开，并说真正见效的是后者。这与外界常见的 RSI 叙事不同。
- **访谈里没有回答的**：Ultra Fast 的定价、云端 agent 的具体产品形态、暂停前沿 RL 的那组"清晰原则"到底是什么。这三处 Berman 都问了，Tibo 都绕开了。
